# 格式与著录规范

## 一、页面与字体

| 项目 | 取值 | 备注 |
|---|---|---|
| 纸张 | A4（595 × 842 pt） | 沿用模板，不自行改 |
| 页边距 | 左右 90 pt（3.17 cm）、上下 72 pt（2.54 cm） | 以模板实测为准 |
| 正文 | 宋体（西文 Times New Roman）小四（12 pt） | 中文必须设 `w:eastAsia`，否则变宋体以外的默认字体 |
| 一级标题 | 黑体四号加粗（14 pt） | "一、本课题研究意义" |
| 二级标题 | 黑体小四（12 pt） | "（一）理论意义" |
| 三级条目标题 | 宋体小四加粗 | "1. 文献研究法" |
| 行距 | 1.5 倍 | |
| 首行缩进 | 2 字符（= 字号 × 2 pt） | 小四即 24 pt |
| 参考文献 | 宋体五号（10.5 pt），悬挂缩进 24 pt | 编号顶格，续行缩进 |
| 表题 | 宋体五号加粗，居中，位于**表上方** | "表 1　×××" |
| 图题 | 宋体五号加粗，居中，位于**图下方** | "图 1　×××（作者自绘）" |

## 二、三线表

只有三条横线：顶线、栏目线（表头下）、底线。**无竖线、无其余框线。**

实现要点（python-docx）：

1. 整表 `tblBorders` 全部设为 `nil`
2. 表头行单元格设 `top` + `bottom`（1.5 pt 与 0.75 pt）
3. 末行单元格设 `bottom`（1.5 pt）
4. 表头文字加粗、居中；正文列左对齐或居中

详见 `docx-recipes.md` 的 `three_line_table()`。

## 三、GB/T 7714—2015 著录格式

### 常用类型标识

| 类型 | 标识 | 示例 |
|---|---|---|
| 期刊 | `[J]` | 作者. 题名[J]. 刊名, 年, 卷(期):起-止页. |
| 网络期刊 | `[J/OL]` | 作者. 题名[J/OL]. 刊名, 年, 卷(期):起-止页[引用日期]. URL. DOI:… |
| 专著 | `[M]` | 作者. 书名[M]. 版次. 出版地: 出版社, 年: 页. |
| 学位论文 | `[D]` | 作者. 题名[D]. 城市: 学校, 年. |
| 标准 | `[S]` | 机构. 标准名称: 标准号[S]. 出版地: 出版者, 年. |
| 法规/公告 | `[Z]` | 机构. 文件名称（文号）[Z]. 发布年份. |
| 电子公告 | `[EB/OL]` | 机构. 标题[EB/OL]. (发布日期)[引用日期]. URL. |

### 作者著录

- 3 人以内全列，用逗号分隔
- 超过 3 人：列前 3 人 + `, et al.`（西文）或 `, 等.`（中文）
- 西文作者姓前名后、姓全大写：`SANGIORGIO A, SIRONE M, ADRAVANTI F M, et al.`
- 中文作者原名，不缩写

### 六类高频错误（逐条核对）

1. **页码不连续**：`47-53` 可能是 `47-49,53` 的误读。核对原刊目录或数据库著录，不要想当然按"起-止"写。
2. **2026 年新刊**：预出版（Epub ahead of print）与正式卷期可能不同步。定稿前查 PubMed/期刊页确认是否已归入正式卷期；未归入的写 DOI + 引用日期。
3. **漏作者**：中文期刊常见 3—4 位作者，只写第一作者会出错。核对数据库著录页。
4. **卷期页缺失**：`[J]` 类必须齐 `年, 卷(期): 页`，缺一项即为不合格著录。
5. **DOI 重复**：`[J/OL]` 已有 URL 时，末尾再加 `DOI:` 需保证两者一致，不重复罗列同一链接。
6. **文献类型标识错用**：法规用 `[Z]` 不用 `[S]`；指南用 `[S]` 或 `[Z]` 视发布形式；网页用 `[EB/OL]`。

## 四、引注与自检

| 检查项 | 方法 |
|---|---|
| 是否有上标 | 检查 run 的 `font.superscript is True` |
| 编号是否从 1 起连续 | 正序提取正文首次出现序列，与 1..n 逐一比对 |
| 是否有孤条 | 统计每条 [n] 在正文出现次数，0 次即为孤条 |
| 文末声明是否属实 | 声明"全部条目均以上标 [n] 标引"前，先跑上面的检查 |

## 五、Word 修订痕迹

python-docx 不能生成 `w:ins`/`w:del` 修订标记。要交带痕迹的稿子，用：

```
Word → 审阅 → 比较 → 比较文档 → 原稿 / 修订稿 → 确定
```

自动生成带修订标记的版本，比手工开修订模式逐字改更可靠（不会漏改）。v1.0.0 不支持自动生成修订痕迹。
