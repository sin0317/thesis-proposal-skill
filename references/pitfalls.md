# 踩坑清单与排查顺序

按"踩到的次数 × 造成返工的量"排序。每条都是真实事故，不是假想。

## 一、内容口径类（会导致评审直接质疑，优先级最高）

### 1. 例数口径三处不一致

**症状**：题目写 1701 例，表里写"约 1700 例"，正文某处写 1767 例，导师问"到底多少例"。

**根因**：把"题名例数逐篇相加"当成实际例数。题名标 126 例的文献，正文可能通篇只有 60 例（各系统分别报 27/60、18/60、11/60）。

**排查**：
```python
# 逐篇比对题名例数与正文最大分母
for f in texts:
    title_n = re.search(r"(\d+)\s*例", title)
    body_ns = re.findall(r"/(\d{2,4})", body)   # 分母
    print(f, title_n, max(map(int, body_ns), default=None))
```

**做法**：表格里增加四行——合计、核减（题名与正文差额）、重叠剔除、预计纳入，并在表下注说明差额来源。

### 2. 把"构成比"写成"发生率"

**症状**：文中出现"ADR 发生率为 23.5%"。

**根因**：分子是已发生的病例，没有用药人群作分母。

**做法**：全文检索"发生率""发病率""患病率"，逐一改为"在汇总的 X 例中占比 Y%"；并加一句边界声明："本研究为描述性汇总，结论限于所汇总病例的特征，不外推总体发生率。"

### 3. 把描述性汇总写成 Meta 分析

**症状**：方法部分写"对率进行合并"，结果部分却只有构成比表，前后不接。

**做法**：明确写"属描述性汇总（narrative summary），不作率的合并、不作假设检验"；引用《上市药品临床安全性文献评价指导原则》说明定性汇总的适用条件（异质性过大时不合并）。

### 4. 字段承诺了却填不出来

**症状**：方法里写"按合并用药、过敏史分组比较"，正文里这几个字段大片空白。

**根因**：没先核实原始文献是否报告这些字段。

**做法**：先做字段可得性核验（表 A），报告率 < 50% 的字段只作定性归纳，不作分层承诺。真实案例：合并用药 47.4%、过敏史 36.8%、因果判定 21.1%，三项均低于阈值。

## 二、引注与参考文献类

### 5. 开篇即 [29]

**症状**：研究动态第一句是"Sangiorgio 等[29]"，前面 28 条从未出现。

**根因**：沿用了上一版的编号，只调整了段落顺序。

**做法**：整表按首次出现顺序重排（`scripts/refs_renumber.py`），并程序化校验"正文首次出现序列 == 1..n"。

### 6. 正文零上标、文末声称"全部被引用"

**症状**：文末写"以上文献均以上标形式标引"，正文实际一个上标都没有。

**做法**：先统计每个 `[n]` 在正文的出现次数，再写声明；0 次的条目要么补引、要么删除。

### 7. 作者-年份制与顺序编号制混用

**症状**："Sangiorgio 等（2024）"与"李某某[14]"并存。

**做法**：统一顺序编号制，作者-年份写法一律改 `[n]`。

## 三、写作结构类

### 8. 研究方法并列 7 项，层级混乱

**症状**：文献调查法 / 文献特征描述性统计 / 内容分析法 / 描述性统计分析法 / 分层亚组比较法 / 纳入文献质量评价 / 一致性复核判据法。

**根因**：把"方法的具体运用"和"质控措施"也当成了方法。

**判断标准**：能独立写出一段"学术依据 + 定义 + 特征"的才是方法；写不出来的，是方法内部的步骤或质控措施。

**做法**：只留 3 个真正独立的（文献研究 / 内容分析 / 统计分析），文末一句交代其余为何不单列。

### 9. 创新点写成"无人做过"

**症状**："本研究首次对盐型差异作比较，填补了国内空白。"

**根因**：无法证明"无人做过"，且评审一查就有反例。

**做法**：改为"已有文献多各自报告单一变体，本研究把不同变体置于同一口径下比较"；删除一切"首次/无人/填补空白"；创新点部分不加任何引注。

### 10. 研究内容写成操作步骤

**症状**："内容一（文献检索）：采用 CNKI 与 PubMed，检索式如下……"

**做法**：研究内容只写产出（建立数据集 / 描述特征 / 识别风险因素 / 提出建议），做法移到研究方法。

## 四、技术实现类

### 11. 校验脚本出现大量假阴性

**症状**：明明写进去的内容，校验报 FAIL，且集中在表格相关条目。

**三个真凶**：
1. `d.paragraphs` **不含表格单元格**——表 3/表 4/表 5 的内容全在 tables 里
2. 全角空格（U+3000）与半角空格混用，`"1 700"` 与 `"1\u3000700"` 不相等
3. 校验串是"我以为的写法"，与文档实际措辞有细微差异（如"随机抽查 20% 复核"vs"由指导教师随机抽查 20% 复核"）

**排查顺序**：
```
① 把校验串拿到文档里做子串搜索（不过 norm）
② 搜不到 → 再 norm（去所有空白）后搜
③ 还搜不到 → 打印该段落/单元格原文，肉眼比对
④ 确认文档确实没有 → 才改文档
```
**先怀疑校验串，不要先改文档**——真实项目里 6 条 FAIL 全部是假阴性，没有一条是内容缺失。

### 12. 合并单元格吞掉标签

**症状**：表 A 新增的"合计""核减"等行，标签列显示为空白或与内容混在一起。

**根因**：先写文字再 `merge`，合并后文字被串联/覆盖。

**做法**：先 `merge`，清空，再写文字（见 `docx-recipes.md` 第 7 节）。

## 五、交付类

### 13. 直接覆盖源文件

**症状**：改完发现改错了，原稿已经没了。

**做法**：一切修改在副本上进行，命名带日期；源文件、模板、导师意见原件永不覆盖。删除前先备份。

### 14. 替用户编造未核实信息

**症状**：课题来源栏自动填了"自选课题"，实际是教师科研课题。

**做法**：未核实项留占位或写"待确认"，交付时用 ⚠️ 单列，明确说"这几项我没臆填"。
